# 一条命令测试题库、对比旧流程与 V2

适用分支：`feat/evidence-v2-optimized`。脚本复用现有 `benchmarks.run` 与原 Worker，不改部署，不运行第二套 Agent，不自动重试。

## 1. 图片与配置

直接使用已提交的命名：

```text
tests/test-items/
├── 01.png
├── 01答案.png
├── 02.png
├── 02答案.png
└── ...
```

支持 PNG/JPG/JPEG/WebP，按数字题号配对。缺图、重复编号、只有答案没有题图都会报错，不静默跳过。只用题图时显式加 `--without-answer`。

已安装项目依赖与 Playwright Chromium 后，不需要启动网站、Redis 或另一个 Worker。脚本优先使用工程的 `.venv/bin/python`；也可设置 `PYTHON=/你的虚拟环境/bin/python`。

真实测试自动读取工程根目录的 `.env`，不需要手工 `source`。已导出的环境变量优先（包括空值）；支持单行 `KEY=VALUE`、引号、注释和 `export KEY=VALUE`，**不执行 Shell，也不展开 `$VAR` 或 `$(...)`**。模型 Key 留在本地 `.env` 或环境变量，不放命令参数。切勿提交 `.env`。

## 2. 最常用的命令

```bash
# 仅列出第01题和将执行的配置；不会读密钥、启动模型或产生费用。
bash scripts/test_compare.sh 01

# 实测第01题：A1（旧流程）对比B0（V2串行），共两个新任务，会调用真实模型。
bash scripts/test_compare.sh 01 --run

# 测前3题，逐题串行运行，每题每个配置只跑一次。
bash scripts/test_compare.sh 01-03 --run

# 整个目录：默认每题A1/B0两组。9道题就是18个新任务，均可能产生费用。
bash scripts/test_compare.sh all --run

# 对照原流程和完整优化配置；也可分别测试B0/B1/B2。
bash scripts/test_compare.sh 01 --profiles A1,B2 --run

# 单独试V2，不运行旧流程。
bash scripts/test_compare.sh 01 --profiles B2 --run

# 单题四组对照：四个新任务。
bash scripts/test_compare.sh 01 --profiles A1,B0,B1,B2 --run
```

| 配置 | 含义 |
|---|---|
| A1 | classic 兼容路径；**不是尚未交付的完整模块化重构分支** |
| B0 | V2 计算计划＋构图编译，串行 |
| B1 | B0＋数学/浏览器两分支并行 |
| B2 | B1＋任务内精确计算结果复用 |

可直接使用 `python -m benchmarks.suite` 代替 Shell 入口。默认只预览；只有 `--run` 才授权列出的真实任务。先用一题确认模型接口与质量，再自行决定是否跑全部。

每个任务使用独立子进程、从同一基础环境重新加载配置；模型、思考强度、Token、调用和任务时间预算沿用配置，不由新脚本缩减。各配置的流程开关仍由已有 `benchmarks.profiles` 控制。相邻题轮换配置先后次序，降低固定 A→B 顺序偏差，不并发抢占本机资源。

第一笔模型请求之前会检查全部配置、图片解码、Python 导入和本地浏览器启动/本地文件读取；预检不访问模型。**它不能验证真实 Key、模型多模态支持或服务器可达性**，这些只有真实请求才能验证。

## 3. 查看报告

每轮自动创建全新目录，不需要手动填写 `--out`：

```text
benchmark-runs/日期时间-随机后缀/
├── summary.html          # 双击查看逐题耗时、模型调用数、输出Token及网页/日志链接
├── summary.md
├── summary.json          # 机器可读汇总
├── suite.json            # 任务清单、输入哈希和运行顺序；不记录密钥
├── logs/                 # 脱敏后的运行器控制台日志
├── 01/A1/                # 原有manifest/result/runtime完整产物
├── 01/B0/
└── ...
```

终端会打印报告路径。成功项提供“讲解网页”链接，失败项保留日志、统计与任务报告，不把未通过复核的草稿当作成品链接。

报告同时列出完成、失败/结果不明、未运行数量；耗时中位数只统计完成项，**完成不等于数学正确**。未做人工质量评审，不报告准确率、不宣称达到180秒正确交付目标，也不编造费用。缺失模型用量显示未知而非零。需要质量评分时仍可使用原 `benchmarks.compare --quality`。

仅重新汇总已有运行（不会调用模型，也不会续跑）：

```bash
bash scripts/test_compare.sh --report benchmark-runs/某一轮目录
```

可用 `--out /全新目录`、`--env-file /私有配置.env`、`--data-dir /其他题库` 自定义路径。不得使用已存在的输出目录覆盖或恢复任务。

## 4. 失败、中断与隐私

同一轮严格串行，同一工程同时只能运行一个本脚本实例。正常任务级失败会保留在汇总并继续下一项，**不会重试失败任务**；运行器没有可信结果、输入中途改变或配置/依赖错误会停止后续任务。

按 Ctrl+C 会通知现有 Worker 监督入口清理当前任务，并停止后续项，保留部分报告。已发出的模型请求可能仍计费。脚本没有自动续跑功能；重新执行 `--run` 是新的付费测试，不是免费恢复。

汇总重建时发现上次仍在运行却没有结果，会标记 `unknown_completion`，不会擅自重发。退出码：0=全部选中任务完成（不代表人工正确）；1=存在失败或未运行；2=输入/配置/预检错误；130=用户中断。

完整运行目录含原题、答案和模型输出，只保留本地，不要上传公开仓库或公开 CI artifact。控制台日志会遮盖已知 Key/Token 值，但这不等于所有原有任务产物均已做隐私清洗。

新增脚本测试只使用临时文件、伪造结果和本机受控子进程，不使用真实模型。真实题时延与质量由你在本地执行 `--run` 后验证。
