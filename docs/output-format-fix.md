# V2 字段纠错与完成态 JSON 接收修复

## 修复范围

本次失败在解题输出接收阶段：部分 `variables` 误用工具参数的数组形式；原有纠正请求重写整份答案，随后因单个多余根 `}` 导致 JSON 解析失败。无 Token 截断，也不是180秒业务超时。

本版保持模型、思考强度、预算、诊断模式、部署及独立复核不变。没有付费模型重跑。

- 最终计算计划的 Schema 描述和提示词明确区分：`algebra_batch` 工具使用变量数组，V2 `computations` 使用变量名到假设的对象。
- 当**全部报错都能唯一定位为 `variables` 数组类型错误**时，只请求这些字段的补丁，不再重写全部证明和画板。保留原始变量名，假设仍由模型依据原题选择；不能确定时允许返回 `null` 并停止，不自动补 `real/positive/nonzero`。
- 补丁绑定原输出哈希，只能覆盖服务器确定的路径；拒绝改公式、期望值、证明、场景、变量名及未授权字段。合并后再次执行完整 Draft、引用/依赖校验，以及原数学计算、浏览器、独立复核和发布门禁。
- 其他不能唯一绑定的验证错误仍沿用原有限次处理，不扩张补丁权限。字段纠正没有增加额外重试次数。
- 只对 API 已完成的输出处理一个非常窄的 JSON 情况：完整单一对象之后多出一个根 `}`。完整对象文本逐字保留；多对象、附加文字、重复键、非有限 JSON 常量、内部语法错误、未闭合字符串及截断状态仍拒绝。
- 记录字段修改路径、前后哈希及合并产物；原始解题 JSON 和字段补丁分别保存。尾括号修复记录原文/修复哈希及移除后缀，不把修复视为数学验证。
- 终端/summary 报告区分 `MODEL_JSON_INVALID` 与 `MODEL_CONTRACT_INVALID`，显示阶段、JSON位置或字段路径；不复制原始模型正文、异常中的输入值或凭据。

## 验证口径

以用户保存的首次解题结果与纠正结果做本地离线回放：仅四处 variables 替换，其余内容与已保存的完整结果一致；合并后通过 Draft 和引用依赖校验。该回放不发模型请求，不等于新题真实独立复核成功。

新增离线回归覆盖补丁越权/旧哈希/漏字段/未知假设、完整依赖校验、JSON边界、历史诊断分类；新增链路测试使用模拟HTTP，覆盖 Chat/Responses、V2串行/复用、字段纠正后多余尾括号及真实负证据仍阻断发布。完整 CI 数量与结果以对应提交的 Actions 为准。
